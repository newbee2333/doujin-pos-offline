# 优惠与调价

使用入口见 [使用说明书](../README.md#28-配置活动价和满减)。本文件说明计算与数据兼容边界。

## 计算规则

- 基准单价始终为本场 `event_price_minor`，商品默认价不参与计算；赠品为零元，不参与满减。
- 活动单价支持固定优惠价或折扣。折扣用万分数保存，八折为 8000；按币种最小单位四舍五入。
- 满减门槛为参与商品的基准单价乘数量之和，取最高达标档位一次。活动价、人工单品优惠不影响资格。
- 实际满减额不超过参与商品在活动价及单品人工优惠后的小计。再计算整单人工优惠，总额始终非负。
- 人工折扣以活动价为基准覆盖之前的人工设置；整单折扣以满减后的金额为基准。商品或数量改变后取消整单人工设置，要求重新核对。
- 满减先在参与行分摊，再在剩余金额上分摊整单优惠。两次均按金额比例、最大余数法分配，平余数按稳定明细 ID 排序；每次分摊之和精确到最小单位。
- 同规格部分件数改价拆成独立行；名称和 SKU 不增加优惠后缀，库存和限购按整单合并校验。

例如三件本场单价 50 元，满 150 减 20，其中一件人工价 40 元：门槛基准 150，调价后小计 140，实际满减 20，应收 120。先改价或先加购，结果相同。全部降到零元时，满减实际应用额为零。

## 安全与待付款订单

人工调价默认要求现有后台密码，连续 5 次失败限速 1 分钟，刷新保留限速状态。设置可关闭此要求，关闭时必须先验证密码。调价原因记入审计，明文密码不进入订单、幂等记录或审计。

待付款调价前需核实未付款，进入调价后锁定确认收款，游客页隐藏付款码。保存后递增价格版本，要求游客或收银员明确确认新应收金额，再允许收款；确认时在同一事务内检查版本、确认状态及调价锁。已经成交的订单不能调价。恢复中断的调价可继续或取消。

系统展示的是静态收款码，无法撤回顾客已经截屏的付款信息，也无法判断外部支付是否到账；二次确认不能替代人工核实付款记录。

## 存储与兼容

- 每场优惠存于 SQLite `settings` 的 `promotions.<eventId>`：一个版本化记录，保存与下单事务校验版本。本项目直接从本机数据库读取菜单，无另一套服务器菜单缓存。复制展会复制优惠配置，移除参展商品清除其活动单价。
- schema 2 → 3 仅增列，不重建订单表、不删历史列。旧行回填 `net_minor=subtotal_minor`；旧订单无快照时保持原金额，不追溯应用当前活动。
- `orders.pricing_json` 保存基准、规则、分摊及整单调整；`pricing_version`、`customer_ack_version`、`pricing_editing` 控制待付款改价。
- `order_items.pricing_json` 保存单行快照，`net_minor` 保存优惠分摊后金额。保留 `subtotal_minor=unit_price_minor×quantity`；订单应收等于全部行 `net_minor` 之和。
- 退款仍退整单应收金额；销售额仍统计有效成交及退款订单的优惠后原销售。优惠单独展示，不作为退款，商品报表按净分摊金额计入收入。
- 本仓库当前实现为本机 SQLite 离线收银（并非另一套在线架构）。保留离线优惠、收银和数据库备份；不引入在线项目的 `checkout_pins`、`menu_revision` 或数据库迁移编号。

## 验证

`pricing.test.ts` 验证门槛与操作顺序无关、零元封顶、排除商品、币种舍入、最大余数分摊；`promotions.test.ts` 使用真实 SQLite 验证拆行限购、交易、退款、报表、迁移、备份恢复与待付款版本保护。

`scripts/verify-promotions.mjs` 用独立浏览器环境走真实配置及调价操作；提供 `PROMOTION_PRODUCTION_BASE` 时，还将临时测试库恢复到生产构建，验证离线关闭重开、满减下单和人工调价收款。该流程不读取个人营业数据库。
