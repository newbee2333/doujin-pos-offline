# 同人摊位电子菜单 · 使用说明书

> **在线使用**：https://doujin-pos-offline.pages.dev
> 备用地址：https://doujin-pos-52877.app.workbuddy.host
> 构建与部署等**开发者文档**见 [docs/开发文档.md](docs/开发文档.md)。
给摊主（和帮摊的朋友）看的操作手册。按"摆摊前 → 摆摊中 → 收摊后"的时间线组织，遇到问题查最后一节。

> 这个系统**完全跑在你自己的设备上**：数据存在本机浏览器里，不联网也能用，没有任何服务器。好处是断网照样收钱；代价是**备份是你唯一的保险**，请务必看第 7 节。

---

## 1. 第一次使用

1. 打开应用（线上链接或本机地址）。
2. 首页会提示**建立新的空数据库**，点它。
3. 进入后台时要求**设置后台 PIN**：输入 4 位数字，**再输一遍**确认。这个 PIN 保护后台和收款确认，**别用生日**，也别告诉帮摊以外的人。
4. 之后每次进后台都会要求**请输入后台 PIN**，输对才能进。

> **PIN 没有找回方式。** 忘了就进不去后台，只能清空本站数据重来 —— **商品和订单会一起没掉**，
> 所以务必定期导出备份（第 7 节）。趁还记得，也可以在「设置 → 安全与访问」里换成一个好记的数字。
> 详见第 9.2 节。

---

## 2. 摆摊前的准备

### 2.1 建一场展会

后台 → **展会** → **新建展会**，填名称（如"冬季例大祭"）。

### 2.2 录入商品

后台 → **商品** → **新增商品**：

- **名称**：顾客看到的名字，尽量和实体一致
- **默认价格**：仅作填表参考，实际售价在展会里按场次设
- **库存类型**：普通库存（卖一件扣自己一件）/ 组合套装（自己没有库存，卖一套按成分一起扣）/ 赠品（不收钱但照常扣库存）/ 不计库存（无料、宣传品）。选完之后下边会有一句话解释这个类型怎么算
- **菜单分类**：新刊、既刊、亚克力、徽章、色纸、套装……只决定它摆在游客菜单哪一栏，**不影响库存怎么算**。可在设置里增删
- **封面图**：**强烈建议每件都传**。游客菜单靠封面认货，没有图会显示"无图片"占位。图片会自动压缩（最大边 1600px），放心传原图

商品建好后点**编辑**可以随时改。

> 「菜单分类」和「库存类型」里都带「套装」两个字，很容易看混：**决定它是不是套装的是「库存类型」**。如果分类选了「套装」而库存类型还是「普通库存」，弹窗会直接提醒你。

### 2.3 把商品加进本场

后台 → **展会** → **全部加入本场**。然后在本场列表里逐行填：

- **本场价格**（可以和默认价不同）
- **库存**：本场带了多少个。套装会自动按组件库存计算可用数
- 如果勾选了"显示精确库存"，游客菜单会显示「剩 N」

### 2.4 套装（组合商品）怎么配

套装 = 把几件商品打包成一个条目卖，例如「三件套」= 1 本子 + 2 吧唧 + 1 色纸。

配法：**商品 → 新增商品**（或选中已有商品点**编辑**）→ 把**库存类型**选成**「组合套装」** → 下边会出现**套装成分**，点「添加成分」，在弹出来的商品卡里挑商品、填数量。改完保存即可。

- 成分只能选**库存类型为「普通库存」**的商品，因为只有它们有库存
- 挑成分的界面就是游客菜单那套商品卡（带封面），商品多的时候可以直接搜商品名 / 规格 / SKU
- 新增和编辑都能配，不需要「先保存再回来补」

现场怎么算：

- **套装自身不持有库存**，它消耗成分的库存。开场时你要给**成分**设初始库存，而不是给套装设
- 卖出一套，系统按成分数量**同时扣减**那几件商品。上面那套卖出 2 份 = 本子 −2、吧唧 −4、色纸 −2
- 同一单里既买套装又单买成分，需求会合并计算，不会各扣一遍
- 哪件成分不够，**整单都会被拦住**（不会只扣一半）；退款、纠错时按成分各自返库
- 库存流水记在**成分**上，套装自身没有流水
- 摊主收银台上，套装显示的可卖数是**按成分算出来的**（各成分可用数除以用量取最小）

成分**不必单独上菜单**。你可以只把它挂进套装、不加入本场单独卖——这时它属于报表里的「仅作套装成分」，备货仍然要算给它（见第 6 节报表说明）。

> ⚠️ 成分挂进套装之后，**别用「从本场移除」把它整行去掉**。移除后「库存」页就没有它那一行了，现场缺货时你会找不到地方给它补货，而套装还在照常扣它的库存。本次不卖、以后还要补货的话，用**下架**就够了。真要点移除，确认框会提醒你。

### 2.5 配置支付方式

后台 → **展会** → 支付方式：

- **本场启用**：勾选这场要用的（如"现金"）。扫码方式必须先上传收款码，游客才能选它
- **模板启用**：不勾选的话，之后新建的展会不会带它
- **确认需输 PIN**（默认勾选）：
  - 勾着 → 游客下单后，摊主要输 PIN 才能确认收款
  - 取消勾选 → 游客下单后，摊主**直接点确认即可**
  - 判定按**游客下单时选的支付方式**算。例：给"现金"关掉 PIN，现场就不用反复输

### 2.6 开场

后台 → **展会**：

1. **检查开场条件**：价格、库存、至少一种可用支付方式齐了才会过
2. **开场**

开场后游客菜单才会接受下单。未开场时游客会看到"本场展会当前是草稿状态，暂时无法下单"。

### 2.7 用菜单预览检查效果

商品页和展会页都有**预览菜单效果**。里面可以切换三种画框（平板横屏 1180×820 / 平板竖屏 820×1180 / 手机 390×844），**画框里显示的就是真机布局**。摆摊前用它在 iPad 上过一遍，比现场发现排版问题强得多。预览模式不产生任何真实业务数据。

### 2.8 把它装成 iPad 上的"App"

用 Safari 打开线上链接 → 分享 → **添加到主屏幕**。之后从主屏幕图标进入，全屏显示，没有浏览器地址栏，也更适合游客操作。装好后**首次联网打开一次**让缓存就位，之后断网也能用。

## 3. 摆摊中：游客怎么用（自助菜单）

游客菜单是给顾客的界面，全程不需要 PIN：

1. **浏览**：顶部是摊位信息面板（目录名、在售件数、搜索框），下面是分类筛选。每张卡片以封面为主，图片右上角的小标签表示库存状态：
   - **剩 N**（开了"显示精确库存"时）/ **少量**：库存吃紧，抓紧买
   - **售罄**：封面变灰并盖"售罄"章，且不出现加购按钮
   品名与分类在图片**下方**（不压在封面上——同人本封面顶部常印着书名，压上去会挡住）
2. **加购**：点卡片右下角的圆形 **＋**（价格旁边）；已在购物车里则那里变成数量增减按钮
3. **购物车**：屏幕底部常驻一条（件数 + 合计），点**查看购物车**进详情。每行左侧有商品小图，方便核对"我到底加了哪个"
4. **结算**：**去结算** → 选支付方式 → **提交订单**
5. **付款**：跳到订单页，显示**订单号 #N** 和金额，按提示**把页面出示给摊主核对**，摊主在下一节的两条路径里收款

**闲置保护**：购物车里还有东西但 5 分钟没人操作，页面会提示"长时间无操作，购物车将在 N 秒后清空"，再过 30 秒没响应就清空回到菜单。点任意处即可继续使用。这是为了防止上一个顾客的遗留购物车混进下一单。

## 4. 摆摊中：摊主怎么收款

两条路径，对应两种售卖方式。

### 4.1 路径一：游客自助下单（推荐人多的时候用）

游客自己加购、提交订单（第 3 节），你这边会出现在：

后台 → **待付款**

每一行就是一笔等收款的订单：

1. **选择实际收款方式**（可以和游客选的不同，比如游客选了扫码但你现场收了现金）
2. 现金的话可点**按应付金额**自动填实收，或手工输入（自动算找零）
3. **确认已收款**（零元订单显示**确认发放**，比如免费无料）
4. 收错了就点**取消**，需确认（"摊主核实未收款"）

确认完订单进入已完成，库存同步扣减。

> 这一步要不要输 PIN，取决于游客所选支付方式上的**确认需输 PIN** 开关（见 2.5）。免 PIN 确认**不会**顺带解锁整个后台。

### 4.2 路径二：摊主收银台（推荐人少、或游客不想自己点的时候用）

后台 → **收银**：

1. 从商品网格点**＋ 加入**（收银台的卡片与游客菜单不完全是同一套版式，但用的都是封面图，认货方式一样）
2. 右侧调数量、看应付
3. **收款方式**选现金时输入实收，自动显示**找零**
4. **确认收款并完成** → 提示"已记录收款，找零 ¥N"，库存同步扣减

这条路径在后台里，本来就有 PIN 保护。

### 4.3 改价、取消

- **游客的订单还没确认**：在待付款页点**取消**，或让游客在订单页等摊主处理时直接操作
- **已经确认收款的**：后台 → **订单** 里可以发起更正/退款（记录会留痕，报表可查）

## 5. 摆摊中：库存与看数

- **库存**：每件商品的 初始 / 实际 / 预留 / 可用 四个数实时更新。套餐按组件库存算
- **改库存**：数量**设过之后不能直接改数字**——要改就去「展会配置」的参展商品表里点那行的**调整**（或库存页的调整），选原因（补货 / 盘点调整 / 报损…）并填数量。每次改动都会记进**库存流水**，收摊对账时能一条条查回去
- **订单**：所有订单及其状态（待付款 / 已完成 / 已取消）
- **报表**：按支付方式、商品维度的销售汇总，收摊前可用来对现金

## 6. 收摊

1. 先把**待付款**里的订单全部**确认已收款**或**取消**——还有未处理订单时**收摊会失败**，这是故意的（防止漏收款）
2. 后台 → **展会** → **收摊**
3. 收摊后首页会出现**立即导出**的提示——这就是第 7 节的备份，别点稍后

收摊后游客菜单不能再下单；数据全部保留，下次开场前可继续用或复用商品。

需要查看或分享营业数据：打开 **报表与收摊 → 导出 Excel 营业报表**。一个文件包含营业总览、商品销售、收款汇总、订单、订单明细、库存、库存流水和现金流水。总览先显示销售额、退款和净销售额，再分组列出订单、钱箱及商品销售前五名。明细使用浅色表头，支持筛选；表头和状态使用中文，金额按元／日元显示，时间按展会时区显示。默认不冻结窗格，避免 Excel / WPS 绘制明显分隔线。

报表可以离线导出，在下载列表或 iPad「文件」中确认保存。原始 CSV 保留在 **更多导出** 中，供已有分析工具使用。Excel 报表不能用于恢复数据库，完整备份仍使用下面的 SQLite 导出。

页面上还有一张 **库存消耗明细** 表，回答的是「箱子里少掉的东西都去哪了」。每行一件商品，六列：

- **商品**：商品名 + 规格（有 SKU 的一并列出）。按商品名认，不用去猜「默认规格」是哪件
- **套装带出**：随套装一起卖掉的件数（套装按成分展开算，一套带 2 个就记 2）
- **单卖**：单独卖掉的件数
- **合计售出**：上面两者之和
- **返库**：退款、纠错退回来的件数
- **净消耗**：合计售出 − 返库，也就是这场真实从箱子里少掉的量

这张表**不含金额**。套装是整单收一笔钱，把收入按比例拆到各个成分上是人为定的——所以收入看上面的**商品排行**，这里只看库存去了哪。备货复盘时，用**净消耗**对箱子比**销量**更准。

「库存」表有一列 **在场状态**，用来分辨三种情形，它影响你怎么读这张表：

| 取值 | 含义 |
|---|---|
| 在场 | 还在本场的参展商品里，正常在卖 |
| 仅作套装成分 | 没单独上菜单，但被某个在场套装消耗。备货是给它算的，不能当闲置库存 |
| 已移出本场 | 已经不在本场卖了。它的库存记录会**保留**（以后再加回来还在），所以这行还会出现，但它不参与本场销售 |

前两种的实物库存都还在箱子里、都要算进备货；只有第三种是「货可能还在，但这场已经不算它了」。
把商品从本场移除时（展会配置 → 移除），名册行会删掉、库存与流水保留，所以报表里靠这一列区分。

## 7. 备份与恢复（最重要的一节）

**所有数据只存在这台设备的浏览器里。** 清除浏览器数据、重装系统、设备丢失，数据就没了。唯一保险是导出备份文件。

- **导出**：后台 → **备份与恢复** → **保存当前数据库**（按钮写的是「导出 SQLite」），会下载一个 `.sqlite` 文件。**传到网盘或电脑上存一份**，别只留在 iPad 的下载文件夹里
- **确认保存**：下载不等于文件真的落盘。导出之后要到平板的「文件」里亲眼看到那个文件，再点「我确认已保存」——首页的备份提醒和下面新建空库的警告强度，认的都是这个时间戳
- **何时导**：每天开场前一次、收摊后一次（应用超过 2 小时没备份会在首页提醒，超过 24 小时会强提醒）
- **恢复**：新设备或出事之后 → **备份与恢复** → **选择 SQLite 文件恢复**，选之前导出的文件即可，商品、订单、设置全部回来
- **破坏性操作自带保存入口**：**从文件恢复**和**新建空数据库**这两张卡里，各内嵌了一个同样的「保存当前数据库」，都排在破坏性按钮前面，不用先滚回页面顶部

换新 iPad 的标准流程：旧设备导出 → 新设备装应用 → 恢复 → 完成。

### 7.1 想清空重来：新建空数据库

后台 → **备份与恢复** → **新建空数据库**。它会建一个全新的空库：菜单分类与支付方式回到默认，商品、展会、订单、收款、退款、纠错与现金流水都不带过去。

**这是这个应用里唯一会丢掉营业数据的操作。** 动它之前先看一眼卡片上的提醒：

- 显示「最近一次确认保存：…」→ 你已经存过备份，勾一个确认框就能继续
- 显示「还没有确认保存过任何备份」→ 这台设备一次都没存过。这时要多勾一个「我知道现在这个库里的数据将无法找回」

点开确认面板之后，里面还有一个「保存当前数据库」，就在两道勾选上方。顺序和现场一致：先导出、在平板的「文件」里确认，再回来勾那两句话。

旧库不会立刻从设备上抹掉，但**界面上没有任何入口能再打开它**——所以别把它当备份。能把你带回来的只有你自己导出的那份 `.sqlite` 文件。

**从文件恢复**那张卡也是同样的安排：一个「保存当前数据库」压在上面，下面才是「选择 SQLite 文件恢复」。

当前展会还在进行中时，确认面板会额外警告一次：记得先收摊并导出这一场的报表。

什么情况该用它：把演示数据清干净再正式开场、或者库被折腾乱了想从头来。只是「换一场展会」不需要它——建个新展会就行，商品和设置本来就留着。

## 8. 常用设置

后台 → **设置**：

- **安全与访问**：修改后台 PIN。改完不会把你踢出当前会话，**下次进入后台时生效**
- **存储与离线状态**：查看本机数据库占用和离线可用性
- **备注**：给这台设备留个标记（如"主收银 iPad"），多设备时有用

> 「库存展示」不在这里。它其实是个**逐商品**的开关——要调的是"哪几个商品露库存"，
> 所以放在后台 → **展会配置** → 参展商品表的**精确库存**列，点列头的 **?** 有说明。
> 早先设置页里那个全局开关已经去掉：它和逐商品开关重复，而且会让人以为
> 改了它就等于改了全部商品。

## 9. 常见问题

### 9.1 游客点了"提交订单"白屏 / 卡住

旧版本的一个 bug（已修复）。如果还遇到：刷新页面（下拉刷新或重新打开），订单仍在"待付款"里，不会丢单。请把线上链接重新打开一次以获取新版本。

### 9.2 忘了后台 PIN

**PIN 没有找回方式。** 它只存在这台设备上，没有邮箱验证、没有安全问题、也没有自助重置 ——
一旦忘了，最后的办法是清空本站数据重来，**商品和订单会一起没掉**。

所以在忘掉之前，趁现在还能进后台：

1. **设置 → 安全与访问 → 修改后台 PIN**，换成一个你记得住的数字（输两遍确认，下次进后台时生效）。
2. **展会配置 / 备份恢复 → 导出备份**，把 `.sqlite3` 文件放到设备之外（网盘、另一台设备都行）。
   有备份的话，最坏的结果是重开一个库再把备份导回去，不是从头录一遍商品。

> 清空数据的方法取决于浏览器：Safari 在「设置 → Safari → 高级 → 网站数据」里按站点删除；
> iPad 上也可以在「设置 → 通用 → iPad 储存空间」里找到本站删掉。

> 另外，这个 PIN 的作用是**防止游客误触后台**，不是安全认证 —— 它挡不住一个存心要进后台的人。
> 真要防人（比如设备会长时间离开视线），请用 iPad 的「设置 → 辅助功能 → 引导式访问」
> 把设备锁在本应用里，那比 PIN 可靠得多。

### 9.3 收摊点不动

一定是有**待付款订单**没处理。去后台 → **待付款**，逐笔**确认已收款**或**取消**，再收摊。

### 9.4 游客菜单上商品是灰的

两种可能：库存为 0（显示"售罄"），或展会还没开场（游客侧会提示"暂时无法下单"）。去展会页确认状态，或去库存页核对数量。

### 9.5 断网了还能用吗

能。一切功能（下单、收款、改库存）都在本机完成。**备份导出需要网络**（要下载文件到本地），所以别等到断网才做第一次备份。

### 9.6 游客的购物车突然被清空了

5 分钟无操作的保护机制（见第 3 节末尾）。提示出现时点一下屏幕就能续命。

### 9.7 想在开场前检查菜单显示效果

用**预览菜单效果**（见 2.7），三种设备画框可切换，不会产生真实数据。

### 9.8 两台 iPad 能同时用吗

可以各开各的，但**数据不互通**（各自在本机）。建议固定一台作为收银/游客共用机，另一台只做帮摊查数；收摊后以那台的数据为准导出备份。多设备混写同一单目前不支持。

---

### 9.9 「精确库存」要不要勾？

每个商品后面有个**精确库存**勾选框，控制**游客菜单的卡片上显示到什么程度**。

不勾（默认）：卡片只显示粗粒度状态——**售罄**、**少量**，其余情况什么都不标（"有货"是常态，
每张卡都标一遍只会变成噪音）；非库存类商品显示"不限"。

勾上：改成显示**具体剩余件数**，例如「剩 12」。

怎么选：

- **限量本、想催单** → 勾。顾客看到"剩 3"更容易当场决定
- **库存充足** → 别勾。满屏"剩 47""剩 92"很吵，还会让顾客觉得"这么多，不急"
- **库存很少** → 慎勾。看到"剩 2"有些人会以为你要卖完了，也可能被吓退

「设置」里有一个**全局默认值**，新建展会时按它来；个别商品可以在这张表里单独覆盖。

## 10. 一页速查

| 场景 | 去哪 | 做什么 |
| --- | --- | --- |
| 建展会 | 展会 → 新建展会 | 填名称 |
| 加商品 | 商品 → 新增商品 | 名称/价格/封面图；**「库存类型」决定它怎么扣库存** |
| 设价格库存 | 展会 → 本场列表 | 逐行填价格、库存；**改库存要点那行的「调整」** |
| 配套装 | 商品 → 新增 / 编辑 → 「库存类型」选**组合套装** → 在「套装成分」里点卡片挑商品 | 选成分与数量；库存算在成分上，套装自己没有 |
| 改菜单外观 | 商品 或 展会 → 预览菜单效果 | 三种尺寸画框对照，不锁后台 |
| 配支付方式 | 展会 → 支付方式 | 本场启用 / 确认需输 PIN |
| 开场 | 展会 | 检查开场条件 → 开场 |
| 游客自助下单 | 游客菜单 | 加购 → 提交订单 |
| 收款（游客订单） | 待付款 | 选方式 → 确认已收款 |
| 收款（当面卖） | 收银 | 加入 → 确认收款并完成 |
| 看卖了多少 | 报表 / 订单 | 金额看**商品排行**；东西少在哪看**库存消耗明细** |
| 收摊 | 展会 → 收摊 | 先清空待付款 |
| 备份 | 备份与恢复 → 保存当前数据库 | 每天开场前 + 收摊后；导完要在「文件」里确认 |
| 清空重来 | 备份与恢复 → 新建空数据库 | **先导出确认保存**；旧库界面上回不去 |
| 换设备恢复 | 备份与恢复 → 选择 SQLite 文件恢复 | 选备份文件；卡里自带「保存当前数据库」 |
